# 题库管理第三阶段：后台备份与本地保存状态

## 完成的行为

- “下载完整备份（ZIP）”和图片修复页的完整导出共用后台任务。点击立即出现进度卡片，随后可以继续浏览、检索、编辑，卡片可收起。
- 后台 Worker 直接读取 IndexedDB；题目、使用记录、设置在同一个只读事务中形成一致快照。之后的修改不会混入正在生成的文件。
- 读取和基线核对显示实际条数，整理显示已检查项数和独立资源数，压缩显示 JSZip 的实际进度；前期不显示虚构的百分比。
- 全局只允许一个备份生成任务。支持取消后重试，失败后按钮恢复；不支持 Worker 或加载失败时明确提示，不回退到会阻塞页面的主线程压缩。
- 成功后发起浏览器下载，同时保留“重新下载此备份”链接。文字说明“已生成、已发起下载，请确认保存”，不会宣称磁盘文件一定保存成功。页面离开或下一份备份生成时释放旧文件地址。
- “备份与恢复”中新增保存状态：已写入的题目/使用记录数量、上次生成时间、相对快照新增/修改/删除的题目数及使用记录、草稿/目录/管理记录变化数。编辑器尚未写入的数据不算已保存。
- 管理页显示持久化保护状态，提供用户主动申请按钮，显示整站同源用量和配额估算。拒绝申请、API 不支持或查询失败都有可见结果，不影响题库正常使用。

## 备份基线和兼容

- 使用完整记录的 SHA-256 基线，计算放在后台；对象字段排序，并规范旧草稿指纹，防止备份格式转换和字段顺序产生假改动。
- `bankLastBackupV1` 记录本浏览器成功生成的时间和对应快照；`bankBackupSnapshotV1` 随 ZIP 保存快照基线。生成取消或失败不覆盖上次记录；恢复 ZIP 后可继续比较快照。重新下载相同文件不会清零随后发生的修改。
- 两个内部基线记录不参与变动统计，也不会重复嵌套增长。其余题目、图片、审核、草稿、修订历史、使用记录、目录和导入记录继续使用第一阶段的统一 V2 包。
- 数据始终在本机处理，备份内容不上传服务器。

## 存储隔离核对结果

主页和题库明细页目前均使用同源的 `PhysicsTrainingBankV1`。IndexedDB 按网站源区分，不按 GitHub Pages 仓库路径区分；同源且使用相同数据库名的其他部署可能共用题库。本阶段保留原库名称，保证已有题库无需重新导入，没有实施数据库更名、迁移或删除。界面的“数据存放范围”说明这一点。若后续实施仓库级隔离，必须先验证原库的完整迁移及切换失败后的回退，不能直接换名后显示空库。

## 验证

- 新增 `npm run test:backup`：3500 道长题干，在后台读取/核对/整理/压缩期间继续检索、收起卡片、编辑数据库；检查取消/重试、重复任务拦截、快照一致性、新增/修改/删除各一、草稿和使用记录变化、同文件重新下载、恢复后零假变化、持久化拒绝、API 缺失、Worker 加载失败以及 390px 移动视口。
- 本机大题库测试中 20ms 心跳持续运行，完整成功生成期间获得 155 次心跳，最大间隔约 32ms；这是当前测试环境的结果，不是所有设备的耗时承诺。
- `npm test`、`npm run test:management`、`npm run test:package`、`npm run test:editor`、`npm run test:preview`、`npm run test:word` 通过。统一包和实际图片修复页导出、完整恢复及旧草稿/历史兼容已回归。
