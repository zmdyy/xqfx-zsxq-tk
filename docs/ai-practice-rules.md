# AI 短练习推荐规则

规则版本：`20261030-internal-tasks-v5`。实现入口为 `ai-practice-rules.js`，由核心模块、页面和选题依据共同使用。

## 请求与检查

每次正式推荐都发送 system 规则、版本号、`teachingContract`、逐次成绩、作答状态、原题、知识星球关系和候选题。候选包含原始难度、完整题干、答案与本地任务分析。返回后校验候选 ID、有效证据、考试关系、计分范围、完整题范围、题量、基础起点和已发现的解析冲突；最多自动修正一次。DeepSeek、GLM 和自定义兼容接口共用业务规则。

成绩在模型输入阶段补充 `examRole`、`scoreScope`、`subpartScoresKnown` 和推断限制，不改动旧成绩数据或旧结果指纹。本次其他题不属于历史考试；整题失分不能定位具体错空。引用编号有效不代表错因或学科内容已经证实。

默认一至两道完整题，允许一道结束。计算基础补偿优先独立公式直代，不能将综合题中某个简单小问描述成整题简单。候选从全部匹配题中重新排序，先按任务类型匹配，再考虑知识点相关程度、低负担和基础起点，不只截取旧排序前十二题。独立直代是优先起点，不是精确题型硬门槛。未确认时继续由模型检查短小候选；缺精确直代时允许同技能低负担基础题作为有局限的草稿，说明未满足需求。仅有跨技能或高负担综合题时返回缺题，不编题。基础技能可以使用不同装置情境，不能因同是继电器就将概念题代替计算。概念和实验任务不强制公式题。

## 保守分析的边界

任务类型、直代可能性、负担和局部矛盾目前采用按内容缓存的本地启发式分析，明确标记为 `probable` 或 `limited`，没有调用付费 API 预标注全部题库。单位、公式依赖、隐含条件及图片语义仍可能有遗漏；“未识别到基础题”不等于数学证明题库不存在基础题。

解析检查能发现部分明确的状态定义错误，以及答案分段对同一量偏差方向的矛盾，不代表全部解析已验证。检查针对答案及解析，不能将选择题中的错误选项当作题库错误。发现明确冲突时排除候选，不擅自改写原始题库。

原题排除增加长文本及数值匹配；原题文字缺失时尝试从同科原卷 Markdown 恢复带空格的题号。图片仍会发送给支持视觉的模型。仅凭通用图题短句不会判定为同题；只有图片、缺少文字与来源信息的原题，不能保证自动识别全部变体。当前不自动拆取小问，以免遗漏公共条件、图像或对应答案。

## 复用与导出

规则更新不会自动使旧付费推荐失效，不会因打开页面、切换模型、查看依据或导出而调用 API。旧结果可继续使用；页面提供明确的当前学生更新入口，失败则恢复旧结果。待审核题仍可选，不恢复逐题人工审核关卡。

Word 与选题依据使用相同导出编号和固定快照；依据同时记录所选人数、各人状态、实际进入 Word 的匿名序号和题目版本。快照只保留最近一次，图片复用任务资产。之后发生修改，当前依据会明确标明与此前 Word 不匹配，需重新导出 Word 获得一致快照。

AI 练习导出采用保守版面预算，将题目页和解析页成对交替排列，继续附反馈表；删除仅作为重复说明的末尾“分析”段时保留具体解答。网页预览用于阅读，Word/WPS 因字体和公式排版可能产生分页差异；超大不可拆表格、复杂公式等仍需后续样本验证。普通题库组卷保持原有导出路径。

依据仅手动导出，不含密钥或模型内部思考全文。不得向公开仓库提交学生原始成绩、私有题库、上传附件和测试渲染文件。

## 验证

- `npm run test:ai-practice`：跨知识点基础起点、全候选扫描、证据范围、规则请求、输出校验、快照、复用、反馈表和原生 Word XML。
- `npm run test:ai-practice:browser`：真实浏览器中的规则请求与修正、滚动预览、结果复用、模型切换、脱敏依据和 Word 下载。
- `npm run test:score-groups`、`node tests/report-title-import.test.cjs`、`node tests/full-data-backup.test.mjs`：计分关系、导入和备份兼容。

测试不使用真实密钥或付费模型调用。模型对真实题目的教学判断继续通过不同知识点、题型与学生样本迭代，不能仅以格式校验通过认定推荐正确。

分析步骤只引用证据编号，程序在每条引用的 evidenceContext 中附上考试关系和计分范围。兼容旧模型多填的范围字段，记录差异而不触发付费重试；未知证据编号仍拒绝。更新失败恢复旧结果时保留 lastUpgradeAttempt，导出依据（包括旧 Word 快照）同时包含失败请求，明确区分成功结果与失败尝试。

直代优先适用于独立计分、任务明确的单一计算；混合任务不强制。未被本地启发式确认、或模型未完整填写 foundationAssessment 的短题，记录语义待确认提示，不因此自动付费重试。模型提供的公式和代入式是说明，不代表程序已经验证学科正确性；多小问综合题仍不能标为独立直代题。前置筛选、失败模型结果随依据导出，便于诊断没有成功结果的任务。

## 原题对照与可选教师反馈

推荐页始终展示原题对照，注明当前计分项和得分。优先使用已复核截图，包含整题共享条件；无图时提示缺失并提供已有文字。页面不会把整题得分解释成某小问失分，也不会假装已经定位截图中的具体小问。

整份练习与每道推荐题均可填写适合、不太适合、暂不能判断；不太适合可多选目标不符、太难、太简单、题量过多、前置跨度大、原题重复、题目／解析有误、原题或计分范围不清、其他，并可补充备注。反馈是可选的，不阻止预览或导出，不改变题库审核状态，不会自动再调用 API。教师反馈保存在任务中，随完整备份保存。

每次反馈保留生成时间、依据指纹、当时原题、推荐题快照、AI分析摘要、知识关系、选题理由、范围和反馈时间。换题和再次生成后保留历史反馈；旧反馈不自动套用到新题。匿名依据中的 teacherReviews 包含所有学生的原题与反馈（包括生成失败者），students[].teacherFeedback 随成功结果提供。Word 导出后补充的反馈也会进入匿名依据，与原始 AI 分析分别保存；不改写已有 Word 内容或使付费结果失效。自由备注导出时隐藏本任务学生姓名与当前密钥，请勿填入其他身份信息。原题及题图可能含页面原有文字，截图不会进行图像内身份识别或涂抹。

教师判断是对练习适合程度的评价，不是学生错因已经证实；后续通过跨题型样本改进通用规则，避免为单一道题硬编码。

## 内部任务信息与两次 AI 之间的信息传递

新版下载标注包采用兼容的 1.1 格式，在每个 part 增加 task_context：一句话任务、内部任务类型、原文依据、共享条件、图片依赖和不确定性。知识点仍使用原有规范目录；这些任务类型不构成另一套知识点目录。导入时保存标准化字段与 annotation_original 原始标注项，不要求用户增加任何操作。旧 1.0 JSON、旧批次无此字段时继续工作，不自动调用 API 补齐。

任务信息保存在 questionConceptMap 的 part 内，复用现有批次持久化与完整备份链路；导入保存失败会回滚本次映射修改，保留原标注。除了已存在的无效 ID、重复计分与题号检查，还拒绝明显属于其他题目或科目的成绩列绑定。内部字段不出现在导入状态、知识点标签、推荐页面的原始证据展开区、学生 Word 或反馈表中；匿名选题依据与备份保留完整信息。

候选排序优先显式任务类型，再考虑知识相关与负担；保留全匹配库中的基础计算候选。对于明确标注的控制变量、数据分析或设计任务，可额外提供最多四道同类方法候选，标记 task_supplement，仍检查题干、答案、难度、原题重复与近期布置。方法相同只是召回线索，须由模型比较具体训练价值，不改变原标注或断言学生该能力薄弱。历史证据可补充每次考试最多两个有任务标注的同类任务单元，标记 same_task_only，不能冒充同知识掌握证据。

推荐沿用一次正常调用：先返回 taskReview 核验原题当前计分项及标注，再为每道选择返回 alignment，说明原题任务、候选实际任务、共享技能、降低与新增要求和局限。这些信息只保存到匿名依据，不增加页面展示。旧结果或新字段缺失时记录语义待核验提示，不因新增语义字段自动付费重试；不存在的题目或证据等硬错误仍按原流程拦截。文字引用检查 annotationAudit 仅证明某段引用能否在现有 OCR 中定位，不证明标注含义正确；找不到可能是 OCR 或图片信息造成。

原题排除兼容题号变化与字间空格，增加具体题干前缀比对；仅有通用短句或图片变化的题目仍存在识别边界。模型的任务核验与关联说明同样属于待验证分析，不能宣称已经完成可靠的独立语义审查。付费旧结果继续复用，只有用户主动生成或更新才使用新规则。

新增验证：internal-task-context.test.mjs 检查真实标注函数的生成、导入、标准化、隐藏、保存失败回滚及旧格式兼容；推荐流检查模型输入、匿名依据保留、页面和 Word 不泄露内部字段；完整 ZIP 测试检查持久化、备份、恢复后的任务与原始标注项一致。

首次 AI 标注返回的完整 JSON 另外保存在批次 questionAnnotationImports 中，包括文件级知识库版本、共享信息、附加说明与所有原始题目条目。每份映射以 annotation_source_id 指向对应原始导入；相同 JSON 重复导入不重复归档，后续修订保留历史版本，失败导入同时回滚映射与档案。该档案不显示到日常页面，随批次持久化及完整 ZIP 备份恢复，无需重新调用模型生成；API 密钥继续遵循完整备份的排除规则。
