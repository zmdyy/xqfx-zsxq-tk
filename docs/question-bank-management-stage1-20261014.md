# 题库管理第一阶段：统一文件协议与导入安全

目标仓库：zmdyy/xqfx-zsxq-tk。在第二阶段集中入口的基础上完成本阶段。

## 完成内容

1. 新增统一V2读取、生成和校验模块。更新包与个人备份同样使用bank.json、manifest.json和media资源；旧ZIP和标准JSON继续兼容。
2. 完整备份及题图审核导出均采用新协议；题图审核导出补齐完整个人settings，避免草稿和管理记录遗漏。
3. 同图按实际内容SHA-256去重，覆盖题目、原图/候选、答案、重绘、草稿、修改历史、回退和冲突记录；保留原始data URL编码，避免恢复后草稿指纹失效。
4. 旧草稿的JSON全文指纹迁移为短SHA-256校验值，新编辑器兼容旧指纹。迁移发生于新草稿保存及导入导出，不删除原始备份。
5. 导出从同一个IndexedDB只读事务取得questions、events和settings快照；既有导入日志随完整备份保存。
6. 导入执行前检查数据结构、唯一ID、正文、图片及历史资源。损坏/缺图包在写入前拦截，包括受保护题目的资源。
7. Word、JSON题目合并先在独立记录集合计算结果，再按当前数据库状态校验并一次提交；目录更新也采用事务。同一文件的添加、版本更新、完整恢复出现同步或异步存储错误时整体回滚。多文件逐文件处理，先前完成的文件保留且结果分别记录。
8. 更新前读取数据库最新题目，提交时检查题目与题库版本是否被其他操作改动；保留教师历史和补充来源名称。修复无旧contentHash情况下“仅题图变化”无法识别的问题。
9. 提供统一协议文档及旧包转换工具，后续制作更新包复用同一生成器。

## 验收

- `npm test`：现有基础流程通过。
- `npm run test:package`：协议往返、跨历史/草稿资源去重、独立SHA-256向量、旧ZIP/JSON、缺图、内容篡改、错误版本/ID/路径和空备份；真实浏览器下载与空库恢复、旧草稿恢复、教师保护、仅图片更新、三个操作的注入存储故障回滚。
- `npm run test:management`：第二阶段入口、Word/JSON、来源、导入记录、统一备份恢复及多文件范围。
- `npm run test:editor`、`npm run test:review`：编辑、草稿、审核、导航与教师保护回归。
- `npm run test:preview`、`npm run test:word`：预览及Word流程回归。
- 测试只使用隔离数据库及虚构样例，不操作用户正式题库。
